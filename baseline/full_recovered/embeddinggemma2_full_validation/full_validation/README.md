# Full CLIPScore encoder-substitution validation

This continues the preceding 350-image feasibility study. Gemma's literal CLIP
prefix and FactChecking prefix are fixed; there is no new test-based tuning.
Five pinned encoders are used: Gemma, OpenAI CLIP B/32 and L/14, the officially
trained SPECS checkpoint, and a modern SigLIP2 base-patch16-256 baseline.

Read `package_manifest.json` first. Its `status.complete` is false for an
intermediate checkpoint. A checkpoint is resumable work, not a final result.

## Design

- All 7,511 SugarCrepe pairs / 1,560 images; image-disjoint continuation cohort
  3,949 pairs / 1,005 images, excluding all media used in earlier experiments.
- All 1,000 Flickr8k-Expert images / 5,664 non-reference candidate captions;
  the 900 images outside the preceding pilot are also reported separately.
- Image-cluster resampling and image-level sign permutations; multiple
  captions for one image are not counted as independent images.
- All full runs use float32. BF16 pilot results are numerical sensitivity
  checks only. Matryoshka truncation always uses renormalization.
- Gemma/CLIP retain `2.5*max(cosine,0)`. Native SPECS uses `(cosine+1)/2`;
  SigLIP2 uses unclipped cosine with native raw-text preprocessing. Compare
  rankings/correlation, never raw means across these different scales.
- Compression target is fixed: 256d may lose at most 2 percentage points
  versus 768d on new SugarCrepe media, evaluated using a one-sided 95% lower
  cluster-bootstrap bound. A failed bound is not evidence of equivalence.

## Recompute statistics from completed saved vectors

```bash
pip install numpy scipy
python full_validation/analyze.py
python full_validation/analyze.py --human
```

This does not require model weights or images. It requires a complete package.

## Restore media and checkpoints

Python 3.12 was used. Full versions are in `environment_freeze.txt`. The model
files and full original media are excluded to keep the evidence package small.
The exact evaluated bytes are identified in the manifests and receipts.

```bash
pip install torch transformers==5.19.0 sentence-transformers==6.1.0 \
  numpy scipy pillow pyarrow torchvision ftfy regex 'setuptools<81'
python replacement/download_models.py
python full_validation/download_specs.py
python full_validation/download_siglip.py
python full_validation/download_data.py
python full_validation/materialize_media.py
```

The package contains the required SPECS model source snapshot and license from
the exact official Git revision. `spec.pt` is the trained metric checkpoint;
`openai_b32_longclip.pt` is not substituted for SPECS.

## Resume or repeat inference

```bash
python full_validation/run_siglip.py
# Run this concurrently in a second terminal; total budget is eight threads:
python full_validation/run_all.py
```

Individual commands are available in `run.py`. It checkpoints progress after
each image batch and text chunk. Completed outputs are skipped. A new run with
different settings must use a new `runs` directory; existing checkpoint
configuration and manifest hashes are checked before resuming.

To repeat completely, rename `full_validation/runs` to `runs_saved`, and do not
copy old inference files into the new `runs` folder. The preceding study's
vectors are optional; when present, only float32 vectors for identical image
bytes/texts and pinned checkpoints are reused.

```bash
python full_validation/verify.py
python full_validation/negative_control.py
python full_validation/make_report.py
python full_validation/gallery.py
python full_validation/package.py
```

`verify.py` needs restored media to verify all image SHA-256 hashes and author
expert ratings, and independently recomputes every score using scalar float64.
It also checks all 1,000 Flickr images against the image checksums published
by the original CLIPScore authors, preserved at their pinned Git revision.
The original annotations are preserved; no labels are generated by an LLM.

## Limits

Full aggregate results include earlier development media; the unseen cohort
supports the new confirmation. This does not rule out pretraining contamination.
Native preprocessing, context and model sizes differ. The CPU schedule uses
Gemma at six threads while the baseline queue runs at two; runtime describes
this pipeline and is not a controlled latency comparison. Truncating vectors
saves storage, not image-encoder compute. No fine-tuning, learned thresholds,
paid API, audio evaluation, universal hallucination detection or SOTA claim.

Respect the original COCO, Flickr8k, model and source-code usage terms. Mirrors
and packaging do not change the underlying image licenses.
